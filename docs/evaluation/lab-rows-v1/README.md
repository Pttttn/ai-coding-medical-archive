# Лабораторные строки: экспериментальный профиль и серия проверок

Техническая запись AI, 25 сентября 2026. Реализация `a2abe19`, исправление проекции дат `f10bfdf` (`lab-facts-v2`), fixtures заморожены в `73bb451` / `d56ee47` до настройки parser. Это частичная реализация P0/P2a, не завершение Medical Document Processing Pipeline и не клиническая валидация.

## Что работает

`EXTRACTION_PROFILE=lab-rows-v1` явно включает разбор поддержанных лабораторных бланков. По умолчанию остаётся `legacy`. В стандартном режиме и публичном MCP поведение не меняется.

Для документа, начинающегося с «Лабораторные исследования», «Лабораторный отчёт» или `Laboratory report`, annotator читает **страницы существующей source IR**, а не повторно генерирует факты из сырого текста. Поддерживаются четыре колонки с заголовком (pipe/TSV) и строки вида `Показатель: результат единица; референс ...; отметка`. Это ограниченная текстовая грамматика, не восстановление произвольной PDF-таблицы или OCR. Документы других типов используют прежний LLM-extractor. Неподдержанное содержимое лабораторного бланка остаётся в оригинале и отмечается issues; оно не уходит в генеративный fallback, который мог бы выдать непроверенные строки за разобранные.

`lab-rows-v1` содержит исходный результат, comparator, decimal string без потери точности, единицу, исходную запись референса, row-level UTF-8 span/цитату, отдельные RESULT/SPECIMEN/STUDY даты с источниками и явный PATIENT/UNKNOWN. Преобразований единиц, подстановки справочных норм, вычисления отклонений, диагнозов и интерпретации цели лечения нет. Поддерживаются десятичная запятая, знаки `<`, `>`, `≤`, `≥`, научная запись, качественные «отрицательно»/«положительно» и пустые единицы/референсы. Конфликтующие/неполные даты не превращаются в выбранную дату.

В legacy-проекции фактов тип всегда `LAB_RESULT`; точное значение получает `valueNumber`, а граница `<5` — **null** в legacy scalar и исходное `<5` в typed result/valueText. Референс остаётся рядом с измерением. Факт «подтверждён» здесь означает наличие результата в бланке, а не подтверждённый диагноз или пользовательский review.

Backend проверяет hash, ссылку на IR, UTF-8 source spans и соответствие legacy-проекции. Артефакт сохраняется в локальном `ExtractionRun.rawJson`; `GET /api/documents/:id` возвращает `laboratory` только для успешно обработанной текущей версии. В очереди, при ошибке, изменении текста и удалении поле закрывается. Пользовательское исправление остаётся отдельным overlay; исходная аннотация его не подменяет. В UI есть вкладка «Лабораторные строки» с оригинальным знаком сравнения, референсом, датами и раскрываемой цитатой.

Source IR по-прежнему `SOURCE_ONLY`. Медицинский артефакт связан с ней hash, но **ещё не является новой неизменяемой processing revision**. Используется существующее хранение extraction runs, новой SQL-миграции в этом этапе нет. Согласованная активация facts/index, медицинский chunk builder, per-field spans, persisted checkpoints до LLM и полный recipe остаются в P1/P3. Поиск продолжает индексировать исходный текст прежним splitter.

## Набор и критерии

[Оригиналы и manifest](../../../evaluation/ingestion-labs-v1/manifest.json): 12 полностью синтетических TXT, 120 строк. Development: 8 документов/80 строк; отложенная часть: 4/40, другие панель и шаблоны. Split и эталон зафиксированы до настройки; отложенные результаты не использовались для исправления parser. Шаблоны внутри split повторяются, поэтому строки/документы коррелированы. Gold создан AI из исходных шаблонов и **не прошёл независимую медицинскую проверку**. Это отложенная инженерная проверка, не независимое слепое клиническое исследование. VISIT-набор из общего P0 здесь ещё отсутствует.

Scorer сравнивает multiset полных строк: name, raw result, kind, comparator, decimal value, unit, referenceRaw, RESULT/SPECIMEN date, subject, sourceText. Дубликат — FP; пропуск — FN. Поля также считаются отдельно с привязкой к имени/цитате, поэтому перестановка значений между показателями не засчитывается. Backend и runner отдельно проверяют соответствие source span правильной странице IR. Референс оценивается как исходная строка, а не медицинская интерпретация интервала.

Исходники загружаются через обычный NOTE API на пустом Compose без seed; эталон не передаётся приложению. Первый проход создаёт документы, второй и третий вызывают `reprocess`. Runner ждёт конкретный новый job и новый extraction ID. Это три полных обработки одних оригиналов, **не три независимые установки/свежих индекса**. Файл результата не перезаписывается; ошибки и частичные результаты сохраняются.

На итоговом наборе FP/FN — 0 во всех трёх прогонах, 0/12 документов с различающимися semantic hashes между повторами. Legacy извлёк по 64 факта на проход и упёрся в лимит 8 на часть; comparator/референс/роли дат в его контракте отсутствуют, поэтому 0 typed tuples **не означает отсутствие правильного текста или нулевую медицинскую точность**. Общий scalar-критерий исключает границы и качественные значения: для development это 70 строк.

Сумма времени обработки и polling: legacy development 75.45 / 76.26 / 77.23 секунд; lab rows весь набор из 12 документов 11.56 / 11.85 / 12.40 секунд. Это разные размеры набора, не строгий speedup benchmark и не измерение чистой inference latency. Lab rows **не вызывает LLM для извлечения**, embeddings/indexing остаются настоящими. Результат нельзя приписывать устойчивости Qwen или переносить на модельную обработку VISIT.

Агрегаты всех попыток:

- [Исходная незавершённая серия](baseline-attempt-duplicate.json): первый проход выполнен, повторы получили `409 DUPLICATE`. Исправлен runner, не приложение; неудача не скрыта.
- [Полная legacy-серия](baseline-legacy.json): три новых обработки на другом пустом стенде.
- [Development parser diagnostic](development-parser-initial.json): первоначально 78/80; две строки с единицей `10^9/л` исправлены до held-out проверки.
- [Полная новая серия](lab-rows-series.json): все per-case исходы, source/semantic hashes, per-field counts, время и версии.
- [Браузер](browser.json): desktop/mobile, 10 строк, знак `<0.01`, раскрытие цитаты, отсутствие ошибок страницы/общего горизонтального overflow. Проверка выполнена headless Edge/Playwright после сбоя sandbox helper встроенного browser tool.

## Повтор проверки

Создайте отдельный env по `.env.example`. Установите уникальный `COMPOSE_PROJECT_NAME`, свободные loopback-порты, `SEED_ENABLED=false`, `LLM_MODEL=qwen3.5:9b`, `EXTRACTION_PROFILE=lab-rows-v1`. Host Ollama должен уже содержать выбранную модель и `nomic-embed-text`.

```sh
docker compose --env-file .env.lab-eval -f compose.yaml -f compose.host-ollama.yaml up -d --build
# Дождитесь healthy и HTTP 200 /api/health на выбранном API_PORT.
python scripts/evaluate_lab_ingestion.py --base http://127.0.0.1:13003 --split all --repeats 3 --output .local-evaluation/lab-series.json
```

Runner откажется работать с непустым архивом, включая корзину. Для новой независимой серии используйте другой Compose project/новые тома; не очищайте личную БД. Для baseline выберите `EXTRACTION_PROFILE=legacy` и `--split development` на другом пустом стенде. При обновлении существующего стенда после пересоздания backend/AI выполните `restart frontend gateway`, как описано в README. Вернуться к прежнему алгоритму можно через `EXTRACTION_PROFILE=legacy` и пересоздание AI; старые документы автоматически не перерабатываются.

## Проверка дат и перезапуска

На финальной проверке прежних PDF обнаружен отдельный дефект первой проекции: явная `Дата исследования` сохранялась с ролью STUDY, но не попадала в общую `documentDate/eventDate`. Значения проходили старый partial-gold scorer, который дату не проверял; фильтр по периоду терял эти документы. В `f10bfdf` проекция версионирована как `lab-facts-v2`: RESULT при наличии, иначе явно записанная STUDY; при конфликте или некорректной дате — null. Роль в артефакте не переименовывается. Backend сверяет её с исходным заголовком. Исходные серии `a2abe19` остаются опубликованными со своими версиями; date-defect не скрыт их высоким tuple score на других шаблонах.

[Compose down/up](restart.json) без удаления томов сохранил одинаковый hash снимка 32 документов, 32 IR, 140 фактов и лабораторных артефактов. Это проверка сохранности текущего стенда, а не завершённая crash/atomic-activation приёмка P3/P4.


Финальная версия `f10bfdf` отдельно перепроверена на новом пустом Compose: [полная серия](lab-final-series.json), 120/120 × 3 (held-out 40/40 × 3), без ошибок и различий semantic hashes. [Исследовательские даты старых PDF](study-dates.json): до исправления у 6/6 отсутствовала общая дата; после исправления 18/18 новых обработок (6 PDF × 3) сохранили правильную documentDate, все 42 fact dates на проход, исходную роль STUDY и присутствие в выдаче фильтра периода. Все 42 лабораторных факта на проход продолжают совпадать с development gold.

Linux CI финальной реализации `f10bfdf`: **234 AI, 73 backend, 24 frontend**, lint/build/images PASS. [Run 36112212635](https://github.com/ruslan-yusupov-open/ai-coding-medical-archive/actions/runs/36112212635). Тестовый архив с 32 заново обработанными оригиналами оставлен для ручной проверки; прежняя рабочая установка на 8080 автоматически не перерабатывалась.
