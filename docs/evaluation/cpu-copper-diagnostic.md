# Диагностика повторного CPU Ask Archive: Copper Finch

19 сентября 2026 года первый вопрос `What is the Copper Finch visit code?` после успешного добавления новой заметки не прошёл проверку smoke на ожидаемый ответ с источником. Повторный POST того же вопроса, выполненный основным агентом без переиндексации или перезапуска, вернул правильный код, документ и chunk; retryCount=0.

Read-only снимок [cpu-copper-index-snapshot.json](cpu-copper-index-snapshot.json) показывает 37 индексированных документов и 42 чанка. Единственный активный acceptance-документ — 5666b92b-e594-407c-84f1-a951144bf5a0, версия 1. Его единственный chunk f7e37dc0586bc4942cfbe83d3f9e8b2032405f3b0969c82faad25d10e57aaf5a содержит точную строку `The unique Copper Finch visit code is SYN-COPPER-931.`. Старых acceptance-чанков в снимке нет.

Эти данные не подтверждают проблему устаревшего индекса. Наиболее вероятна нестабильность LLM grading или генерации/проверки цитаты; конкретный узел первого отказа не установлен, поскольку внутренняя content trace не записывалась. Повторный успех не превращает первый прогон в успешный. Он должен оставаться известным ограничением воспроизводимости маленькой модели.

Диагностика читала SQLite с mode=ro, не выполняла дополнительных LLM запросов, не переиндексировала данные и не перезапускала общие сервисы. Реализация в рамках этой проверки не изменялась. Все данные снимка синтетические.
