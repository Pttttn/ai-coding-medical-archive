# Второе чтение VISIT: экспериментальный протокол

Версия реализации `9534c96`, исходный extractor `visit-extract-v2` не менялся. Опциональный профиль `clinical-reviewed-v1`, контракт `visit-assertions-v2`. Новый корпус зафиксирован в `38e546f` до запуска оценки: 10 оригинальных TXT / 60 утверждений, development 6/36, held-out 4/24. Есть повторные упоминания одного заболевания у разных людей, разные события одного лекарства, отрицания, неизвестные статусы, абзацы, списки и английский документ.

Gold создан AI. [Лист ручной проверки](../../../evaluation/ingestion-visits-v2/GOLD_REVIEW.md) пока НЕ заполнен независимым рецензентом. Эти числа измеряют согласие с текущим gold, а не установленное клиническое качество. Held-out после публикации результатов нельзя использовать как новый независимый тест при последующей настройке.

## Алгоритм

Первичный разбор сохраняется неизменным. Второе чтение получает полный source block и до четырёх target anchors без первичных классов. До двух попыток при невалидном JSON; отсутствующие, лишние или повторные индексы не принимаются. Альтернативная цитата обязана включать исходный anchor и проверяется побайтно. Python и backend независимо проверяют контракт, source spans, проекцию и согласованность verdict. Это проверка механизма, не независимая клиническая экспертиза.

AGREES сохраняет первичную fact projection; DISAGREES/UNRESOLVED дают OBSERVATION/UNKNOWN для ручной сверки. Альтернативная интерпретация не становится автоматическим исправлением. Ошибка доступности провайдера не допускает raw fallback. Изначально пропущенное утверждение второй проход не восстановит; одинаковая ошибка двух чтений пройдёт. Контекст ограничен исходным блоком, календарная активность болезни и единая activation facts/chunks остаются вне этого среза.

## Критерии

Старая строгая tuple-метрика `score/summary` сохранена: точные границы цитаты входят в критерий. Дополнительная `semantic/semanticSummary` сопоставляет имя и уникальное исходное вхождение, затем оценивает kind, subject, assertion, medicationState и temporality. Статус не используется для подбора удобной пары. Неоднозначные вхождения не сопоставляются; поддельный span не получает кредит. `exactQuotes` показывает совпадение границ отдельно.

`released/releasedSummary` оценивает только AGREES. Все gold-утверждения остаются в знаменателе: отправка правильного результата на сверку снижает полноту. Medication macro F1 исключает NOT_APPLICABLE. Critical promotions учитываются по конкретному вхождению, поэтому другое упоминание того же названия не маскирует ошибку. Это новая диагностическая метрика; прежние gates и прежние отчёты не переоцениваются задним числом.

## Воспроизведение

Для API-серии нужен отдельный пустой архив, включая корзину, `SEED_ENABLED=false`, `EXTRACTION_PROFILE=clinical-reviewed-v1`, реальная Ollama и новый путь output. Пересоберите Compose со всеми используемыми override-файлами. Пример после запуска стенда на UI_PORT=18088:

```powershell
python scripts/evaluate_visit_ingestion.py --base http://127.0.0.1:18088 --dataset ingestion-visits-v2 --split development --repeats 3 --output .runtime/visit-review-development-9b.json
```

Удалённый вариант использует явно разрешённый пользователем сервер; ключ читается только там. Он проверяет original → IR → модель → проекция, но не backend/index/QA:

```powershell
python scripts/evaluate_visit_ssh.py --wsl --ssh-target root@mpc1 --ssh-key-file /etc/llama-q8-64k.keys --model qwen3.8-27b-q8-100k-cuda --dataset ingestion-visits-v2 --split held-out --repeats 3 --verify --output .runtime/visit-review-held-27b.json
```

Сопоставляются две установки, не изолированное влияние размера модели. Remote alias не удостоверяет происхождение весов. Generation recipe, hashes кода, источников и результатов сохраняются оценщиком; содержательные runtime logs и секреты не публикуются.

## Диагностика прежнего набора

Один дополнительный запуск старого held-out на 27B дал strict 26/28, semantic 28/28, exactQuotes 26/28, 0 critical promotions. Оба несовпадения — только границы sourceText. Это объяснение отдельного диагностического прогона, не замена опубликованной серии 26/28 × 3 и не доказательство отсутствия ошибок на новом корпусе.


## Новая development-оценка

| Установка | Повторы | Strict | Semantic до второго чтения | Semantic только AGREES | Critical до → после |
|---|---:|---:|---:|---:|---:|
| Local Ollama qwen3.5:9b, API/Docker | 3 | 14/36 каждый раз | 28/36 каждый раз | 10/36 каждый раз | 1 → 1 каждый раз |
| mpc1 27B, SSH extractor | 1 | 29/36 | 32/36 | 29/36 | 0 → 0 |

[9B полная серия](visit-review-development-9b.json), [27B development](visit-review-development-27b.json), [диагностика старого набора](visit-review-old-diagnostics.json). Первичная и повторная разметка 9B стабильны во всех трёх запусках. На один повтор 9B: 33 извлечённых утверждения, 12 AGREES, 3 DISAGREES, 18 UNRESOLVED; 18 правильных утверждений дополнительно ушли на сверку, критическая ошибка осталась. Суммарное время 18 обработок — 209.9 с. Для 27B development: 35 извлечённых, 31 AGREES, 2 DISAGREES, 2 UNRESOLVED; потеряно 3 правильных, удалена 1 неправильная, 151.8 с за 6 обработок. Это время всего pipeline, не отдельная цена второго прохода; сравнение latency установок не изолировано.

Таким образом, second reading на той же 9B не прошёл критерий полезности: заметно снижает полноту, не устраняя наблюдаемую критическую ошибку. Его нельзя рекомендовать как улучшение стандартного режима. Сохранён как явно включаемый эксперимент и инструмент видимости разногласий. Следующий кандидат для проверки — отдельная модель/правила и независимая ручная разметка; вывод о выборе метода должен опираться на новый зафиксированный тест.

[CI 9534c96](https://github.com/ruslan-yusupov-open/ai-coding-medical-archive/actions/runs/36120532312) полностью прошёл: AI/backend/frontend, lint/build и Docker images. Локально 271 AI passed / 2 platform skips, 97 backend и 26 frontend. Тесты проверяют слепой payload, пропущенные/лишние индексы, недоступность модели, подменённые spans/verdict, сохранность первичного разбора, quarantine и ручных исправлений при повторной обработке в том же профиле. Это не доказательство качества медицинского gold.

Новый отдельный Docker-стенд успешно собран и обработал все 6 development оригиналов по три раза через API. [Browser smoke](browser.json): вкладка разногласий, альтернативная цитата, desktop/mobile, без ошибок страницы и горизонтального переполнения документа. Весь pipeline index → QA, перенос review между профилями и новая независимая установка этим экспериментом не проверялись. Основной пользовательский архив не переключён.


## Отложенная серия 27B завершена

[Все 3 прогона](visit-review-held-27b.json), 4 новых held-out документа / 24 gold-утверждения: strict **20/24 × 3**, semantic **20/24 × 3** до проверки и **19/24 × 3** среди AGREES. Первичный и проверочный hashes совпали во всех повторах. На повтор: 23 извлечённых утверждения; проверка удержала одну ошибочную и одну правильную запись. До проверки FP=3/FN=4, после FP=2/FN=5. Critical promotions 0 до/после; этот счётчик относится к сопоставленным вхождениям и не доказывает безопасность несопоставленных утверждений.

Выигрыш точности сопровождается потерей полноты, а ошибочные записи всё ещё проходят. Поэтому автоматический приём по совпадению двух чтений не принят и для 27B. Следующий шаг — ручная проверка нового gold и отдельный проверяющий подход с измерением одновременно ошибок, пропусков и нагрузки на ручную сверку. Новую held-out часть после этого анализа нельзя использовать для подтверждения качества дальнейшего тюнинга.
