# Техническая запись AI: экспериментальный VISIT, 25 сентября 2026

`clinical-v1` — опциональный первый срез P2b, не завершение P0–P4 и не допуск к клиническому использованию. Исходный SOURCE_ONLY IR остаётся неизменяемым. Модель получает целые абзацы; типизированные утверждения привязываются к точным UTF-8 spans предложения и полного абзаца. Из этой аннотации строятся legacy facts, согласованность проверяют Python и TypeScript.

## Область и ограничения

- Subject PATIENT/FAMILY/OTHER/UNKNOWN; assertion CONFIRMED/SUSPECTED/NEGATED/NOT_CONFIRMED/RULED_OUT/UNKNOWN; medicationState PRESCRIBED/TAKING/NOT_STARTED/NOT_TAKING/STOPPED/UNKNOWN; temporality CURRENT/HISTORICAL/FUTURE/UNKNOWN. Это трактовка источника моделью, не установленный системой диагноз. CURRENT означает момент записи, не сегодняшний день.
- Для лекарств assertion UNKNOWN, отдельное событие в medicationState. В старые факты только PATIENT + CURRENT + TAKING переносится как CONFIRMED. Семейная история — OBSERVATION + UNKNOWN; NOT_CONFIRMED и RULED_OUT не превращаются в подтверждённую болезнь. Полная семантика остаётся в артефакте и цитате, старый формат её не выражает.
- Только заболевания, симптомы и лекарства. Дозы/режим сохраняются в цитате, не раскладываются в отдельные поля. Нет отдельной clinical activity, календарных ролей/точности дат, процедуры/рекомендаций, полной сегментации разделов, OCR/layout. `documentDate/eventDate` VISIT-проекции null, дата загрузки не подставляется.
- Классификация по клиническому заголовку в первом абзаце, не универсальный классификатор. Не более 128 абзацев, 6000 символов неделимого абзаца, 3 абзаца/6000 символов на запрос, 8 утверждений на ответ, 200 на документ. Превышения/отклонения явно в issues; достигнутый лимит не означает полный охват. Отсутствие issues также не доказывает полноту.
- Точный source span гарантирует наличие текста, но не правильность subject/status. Аннотация пока хранится в ExtractionRun.rawJson, не в полной immutable processing revision. RAG chunks ещё не проецируются из этой клинической аннотации, staging/activation P3 остаётся открытым. User review отдельный; старое сопоставление review по типу/имени/дате ещё требует улучшения по плану P3.
- Профиль по умолчанию не включён. Поддержанные LAB по-прежнему обрабатываются детерминированно; публичный MCP и доступ к личному архиву не менялись.

## Набор и метод

12 новых синтетических TXT / 84 утверждения: development 8/56, held-out 4/28. Зафиксированы в `b91367b`, затем до первого модельного прогона в `78830c8` исправлен только регистр 8 названий gold для соответствия источнику. SHA исходников не менялись. Генератор отказывается перезаписывать набор. Gold читается только оценщиком, в приложение передаются оригиналы без предвычисленных фактов.

Отложенная часть использует другие специальности/названия и пары предложений в абзаце; набор мал и стилистически связан. Gold написан AI, независимой медицинской проверки нет. В совокупности с лабораторным набором есть 24 документа и 8 отложенных, но это не закрывает требования независимости и ручной проверки P0.

Серия: первая загрузка `/documents/note`, затем два явных `/reprocess` с новыми job/extraction IDs. Одна установка/индекс, не три независимых развёртывания. Оценщик требует пустой архив, включая корзину, и новый файл результата. Ошибки и пропуски остаются в знаменателе, дубли — FP. Точное совпадение включает name (регистр несущественен), kind, subject, assertion, medicationState, temporality и точное предложение. Macro F1 считается по каждому присутствующему классу с идентичностью name+sourceText; отсутствующие во всём прогоне классы исключены. Critical promotions — сопоставленные по имени ошибочные PATIENT+CONFIRMED и TAKING; несопоставленные лишние утверждения остаются FP, ноль promotions не означает отсутствие всех рисков.

## Попытки

Первая версия `visit-extract-v1`: **39/56 × 3**, каждый раз 9 FP / 17 FN, одинаковые semantic hashes, 0 сопоставленных critical promotions. [Полные агрегаты](development-initial.json). Причины: case-only нормализация названий отвергалась валидатором; FAMILY ошибочно подразумевал HISTORICAL; неизвестный приём и неатрибутированные упоминания интерпретировались слишком определённо.

В `visit-extract-v2` допускается только однозначное восстановление регистра имени из исходной цитаты; сама цитата не нормализуется и не исправляется. Уточнены общие правила временных ролей и неизвестности без примеров из отложенных документов. Параметры генерации сохраняются в processingRecipe (не полный recipe P1).

Первый запуск Compose не состоялся из-за исчерпания default address pools Docker; очистили 9 пустых сетей завершённых лабораторных стендов после проверки отсутствия endpoints. Контейнеры/тома пользовательских архивов не удалялись. Это ошибка инфраструктурной попытки, не успешная оценка модели.

## Воспроизведение

1. Создать отдельный env с уникальным COMPOSE_PROJECT_NAME/портами, `SEED_ENABLED=false`, `EXTRACTION_PROFILE=clinical-v1`, выбранным LLM_MODEL. Не использовать пользовательский архив.
2. Загрузить модели в локальный Ollama и поднять `docker compose --env-file .runtime/visit-eval.env -f compose.yaml -f compose.host-ollama.yaml up -d --build` по инструкции README. Дождаться healthy. Чистые тома нужны для первой загрузки.
3. Из корня репозитория: `python scripts/evaluate_visit_ingestion.py --base http://127.0.0.1:18086 --split development --repeats 3 --output .runtime/visit-development.json`.
4. Отложенную часть запускать на другом пустом стенде, после фиксации кода/параметров: тот же CLI с `--split held-out` и новым output. Не подстраивать prompt по полученным held-out ошибкам и повторно называть этот набор независимым.
5. Сохранить все попытки, сравнить semanticHash по case между повторами, macro F1 и critical promotions; сопоставить modelDigest/processingRecipe/хеши кода/gold. Агрегаты не содержат медицинских цитат, ключей или runtime dumps.

Проверки механизмов не подменяют реальную LLM-серию. Целевой macro F1 ≥0.95 и отсутствие критических повышений оцениваются отдельно от стабильности. Полный ingestion→QA, другая установка/GPU, резервное восстановление и нагрузочные бюджеты остаются следующими этапами.
