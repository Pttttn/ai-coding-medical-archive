# Реальные проверки AI/RAG, 2026-09-19

Это технический журнал агента, а не личный REPORT автора. Все запросы выполнены к локальному Ollama с настоящими qwen2.5:3b и nomic-embed-text. Test adapter в этих прогонах не используется. В JSON сохранены только имена и digests выбранных моделей, без перечня других установленных моделей компьютера.

## Исторический контроль перед bounded inference

Предыдущий результат: [final-control.json](final-control.json), 21 вопрос из ../../evaluation/questions.json. Параметры: chunk_size=900, overlap=120, retrieval_k=5, min_relevant_chunks=1, максимум два corrective-повтора после первого retrieval.

- Первые 10 проверочных фактов: **10/10** — ожидаемое значение в ответе и правильный источник в финальных citations.
- Все 12 exact_fact: **11/12** с ожидаемым значением и источником. Для Rowan (fact-11, отрицание с датой) модель отказалась, хотя исходный документ попал в retrieval. Это сохраняемая известная ошибка; нельзя заявлять выполнение всех 12 фактов.
- Наборы ожидаемых источников присутствуют в top-5 для всех 19 вопросов, где такие источники заданы.
- Отсутствующая группа крови и посторонний вопрос: **2/2** явных отказа, по три retrieval-прохода.
- Обзор, перефразирование, два документа и неопределённый приём лекарства: ответ с нужными источниками в данном прогоне.
- Противоречие Spruce: текст правильно содержит 17 и 19 минут из цитаты исправления, но модель сослалась только на corrected source, не на оба ожидаемых документа. Метрика expectedSourcesCited=false сохранена.
- Совместные проверки expectedTextPresent + expectedSourcesCited + abstentionCorrect: **19/21**. Это результат фиксированной синтетики, а не общая медицинская точность. Проверка expectedTextPresent — прозрачный substring proxy, не независимая клиническая оценка.

## Почему ответ состоит из цитат

Первоначальная свободная генерация давала формально валидные citations, но могла инвертировать неизвестный приём лекарства и отвечать на посторонний вопрос общими знаниями. Усиление одного prompt не обеспечило надёжности. Эти неудачи сохранены в real-900-120.json и real-900-120-final.json.

Окончательный generate_answer вызывает настоящую модель для выбора подтверждающих выдержек. Сервер сверяет каждую с найденным источником и составляет читаемый ответ из исходных цитат с номерами ссылок. Непроверенные пересказы модели не выдаются. При вставленных моделью пробелах восстанавливаются только совпадающие исходные фрагменты; несмежные выбранные строки проверяются по отдельности. Выдуманная цитата приводит к ограниченному повтору и затем к отказу.

Это осознанный компромисс: меньше связного пересказа, возможен ответ на языке исходника, иногда слишком длинная цитата. Проверка буквального происхождения не гарантирует, что модель выбрала семантически правильный документ; Rowan и ранние промежуточные прогоны показывают пределы маленькой модели. Источники и ручная проверка остаются необходимы.

Исходные измерения: retrieval-900-120.json и retrieval-1400-180.json. Обе конфигурации нашли источники; выбрана 900/120, чтобы ограничивать объём контекста на grading/generation при том же наблюдаемом recall. Время первичной индексации около 33 и 9 секунд соответственно нельзя сравнивать как контролируемый benchmark: кэш и прогрев модели различались.

## Extraction и privacy

[real-extraction-privacy.json](real-extraction-privacy.json) содержит реальное извлечение лабораторного показателя, назначения, неизвестного приёма и отрицания симптома с проверенными цитатами/страницей. У source указана дата образца, однако модель оставила documentDate/eventDate null: это известная неполнота, не подставленная техническая дата.

В privacy pass локальная модель обнаружила имя в вопросе; правила удалили email, ФИО, дату рождения и клинику в контексте. Сохранились 4.1 mmol/L, отрицание и 10 мг. Полный текст пакета и вопрос проходят очистку; сервер не отправляет их внешним сервисам. Синтетический тест не доказывает полной анонимности.

## Воспроизведение

Из ai-service после uv sync --frozen:

```powershell
$env:OLLAMA_BASE_URL='http://127.0.0.1:11434'
$env:DATA_DIR='../.runtime/evaluation-900'
$env:CHUNK_SIZE='900'
$env:CHUNK_OVERLAP='120'
uv run python -m medical_ai.evaluate --output ../docs/evaluation/new-control.json
```

Для второй конфигурации задайте отдельный DATA_DIR, CHUNK_SIZE=1400 и CHUNK_OVERLAP=180; добавьте --retrieval-only. Скрипт сохраняет каждый завершённый вопрос немедленно, включая ошибки и неудачи. Смена версии модели требует нового контрольного прогона.

Детерминированные проверки: uv run ruff check . и uv run pytest. На Windows выполнено 29 passed, 1 skipped (Windows не разрешил создание symlink). Linux CI должен выполнить symlink test. Suite содержит настоящий HTTP transport FastMCP Client, ровно четыре tools, индексацию семи форматов, persistence/update/remove, BM25/vector/RRF, граф и лимит повторов, PDF text/scan/error, provenance, privacy и отказ при выдуманной цитате. Эти unit/e2e тесты используют явно помеченный FakeProvider и не заменяют вышеописанный real evaluation.

Все промежуточные real-*.json сохранены как свидетельства итераций. Имя файла real-900-120-final.json относится к промежуточной попытке; последняя версия измерений указана в разделе bounded inference ниже.



## Дополнительная adversarial проверка

После основной оценки выполнены три реальные синтетические privacy проверки: русские имена/телефон/СНИЛС в вопросе и тексте; английские имя пациента, врача, клиника, адрес, полис; команды внутри документа, пытающиеся отключить очистку и вызвать MCP. Первоначальный результат [adversarial-privacy-real.json](adversarial-privacy-real.json) обнаружил утечку известных имён: шаблон пересекал перенос строки и поглощал следующую метку Doctor/Телефон, а модель пропускала имя в вопросе. Это подтверждённая ошибка реализации, исправленная в privacy.py.

Теперь имена из явных меток выделяются только в пределах строки, заменяются во всём пакете устойчивыми псевдонимами; поддерживается перестановка «Фамилия Имя»/«Имя Фамилия». После исправления [adversarial-privacy-final.json](adversarial-privacy-final.json): **3/3** без заданных идентификаторов, **3/3** с точным сохранением контрольных медицинских чисел, единиц и отрицаний. Проверялся настоящий локальный privacy_pass. Клинические косвенные идентификаторы по-прежнему требуют ручной проверки.

Документальные команды не исполнялись: модель вызывается без tool API, pipeline не содержит диспетчера инструментов. При этом модель однажды ошибочно извлекла компьютерную команду как MEDICATION при настоящей цитате. Исправленный extraction v2 отклоняет такие protocol-команды с предупреждением. Финальная adversarial extraction в этом случае оставила facts пустым: это безопасный, но неполный результат, а не успешное извлечение всех клинических фактов. Исходный документ и текст сохраняются для просмотра/поиска.

Строгая валидация JSON-схемы остаётся обязательной с одним повтором. Теперь отдельный факт с неподтверждённой цитатой или страницей отклоняется с предупреждением о неполноте, а не делает непригодным весь валидный документ. Корневой smoke с Copper Finch повторён на host-модели успешно (smokeExtraction в final JSON). Повтор старого prompt на контейнерном CPU для точного title 20260919T090407 также дал валидный JSON за 14.36 секунды; первоначальную ошибку за 143 секунды воспроизвести не удалось. Семантические типы фактов и даты маленькая модель всё ещё может выбирать неправильно; эти поля требуют review.

[linux-adversarial-tests.txt](linux-adversarial-tests.txt): **42 passed, 0 skipped** в отдельном Linux контейнере. В контейнер монтировался только код read-only, без архива. Реально прошли symlink-файл и symlink-каталог за пределы разрешённого корня, соседний каталог с похожим префиксом, traversal/glob aliases, public MCP corpus isolation, лимиты схемы, сохранность медицинских чисел, выборочные отказы provenance и протокольных команд. Зависимости pytest/reportlab установлены только в одноразовом контейнере.

Воспроизведение трёх real privacy случаев: из ai-service установить OLLAMA_BASE_URL на локальный провайдер и выполнить `uv run python -m tests.real_privacy_evaluation`. Скрипт использует только синтетические константы и пишет adversarial-privacy-final.json. Промежуточные неудачные JSON сохранены.



## Актуальная bounded inference версия

Последний полный контроль после изменения ограничений генерации и strict JSON: [bounded-final-control.json](bounded-final-control.json). Совместная метрика теперь **17/21**, а не исторические 19/21: первые десять проверочных фактов **10/10** с нужными citations; все exact_fact **11/12**; отсутствие ответа и посторонний вопрос **2/2** корректных отказа. Остались четыре ошибки: Rowan выбрал цитату о похожем симптоме из другого датированного документа, overview дал слишком узкий фрагмент, вопрос о неизвестном приёме лекарства получил ложный отказ, Spruce содержит обе длительности в corrected quote, но ссылается лишь на один из двух ожидаемых источников. Все результаты сохранены, ни один неудачный случай не исключён.

Причина изменения runtime: при default Docker CPU модель могла продолжать структурированный ответ тысячами токенов до HTTP timeout. У каждого /api/chat теперь есть жёсткий num_predict; увеличение timeout не используется как решение. Defaults:

| Операция | Output tokens | Context tokens |
|---|---:|---:|
| Rewrite / broaden | 128 | 8192 |
| Per-chunk grading | 256 | 8192 |
| Grounded answer | 1024 | 8192 |
| Extraction | 2048 | 16384 |
| Privacy pass | 1024 | 16384 |

Настройки: LLM_QUERY_MAX_TOKENS, LLM_GRADE_MAX_TOKENS, LLM_ANSWER_MAX_TOKENS, LLM_EXTRACTION_MAX_TOKENS, LLM_PRIVACY_MAX_TOKENS. Extraction schema дополнительно ограничивает число фактов одной части (EXTRACTION_MAX_FACTS_PER_BATCH=8) и длину строк. Достижение лимита фактов создаёт явное предупреждение о возможной неполноте. Это ограничивает повторение массива моделью; оригинальный текст сохраняется целиком. Полнота извлечения сложных документов не гарантируется.

Ответ с done_reason=length целиком отвергается, даже если выглядит похожим на JSON. MODEL_OUTPUT_LIMIT и MODEL_OUTPUT_INVALID отделены от настоящего HTTP/provider сбоя MODEL_UNAVAILABLE. Schema проверяет типы, обязательные и дополнительные поля. Невалидный grading не считается доказательством; после ограниченных corrective-проходов возвращается отказ. Невалидные выбранные цитаты также не выдаются. Недоступность сервиса остаётся явной ошибкой 503 и не маскируется как отсутствие сведений.

[bounded-inference.json](bounded-inference.json) содержит отдельный real host probe с фактическими num_predict, num_ctx, eval_count, done_reason и временем каждого вызова. До удаления Copper Finch вернулся правильный код с его источником за 1.016 с; после удаления — отказ за 0.813 с; посторонний вопрос — отказ за 1.828 с и три retrieval. Одностраничный seed/originals/lab-01.pdf обработан за 7.672 с, 258 output tokens при лимите 2048: три факта с provenance.page=1, включая оба анализа в проверенных цитатах. При этом модель оставила числовые поля null и выдала неподтверждённую интерпретацию «normal range» в AI-summary; такая сводка и типы фактов требуют review и не считаются клинически проверенными. Это честная граница текущего extraction quality, несмотря на успешный transport/schema.

[linux-bounded-tests.txt](linux-bounded-tests.txt): **59 passed, 0 skipped**. Дополнительно проверены num_predict каждой операции, strict JSON, truncated output, malformed schema, неизвестные поля, безопасный отказ после трёх retrieval и сохранение 503 при реальной недоступности модели.

Воспроизведение targeted probe: из ai-service `uv run python -m tests.real_bounded_evaluation` с локальным OLLAMA_BASE_URL. Нужны root sample_docs и seed/originals/lab-01.pdf. Скрипт использует отдельный временный синтетический индекс и не читает архив приложения.
