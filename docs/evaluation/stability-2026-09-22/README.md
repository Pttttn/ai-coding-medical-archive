# Серийная оценка qwen3.5:2b — 22 сентября 2026

Техническая AI-запись. [Окружение](environment.json): отдельная Docker Ollama 0.34.1, NVIDIA RTX 5080, seed 42, 42 синтетических файла / 773 чанка / 900/120. В каждом опыте заранее объявлены пять повторов с одним persistent-индексом и три с новыми индексами. Все 21 вопрос и критерии PASS сохранены. Прогоны последовательные; число повторов не выбиралось по результату.

## Полная исходная серия

[Сводка](before/summary.md), [все попытки](before/series.json), [диагностика](before/analysis.json), [профиль](before/profile.json).

Все восемь полных прогонов дали **18/21**, первые десять — **10/10**, privacy — **21/21**. При этом в 26 сравнениях вопроса с первым прогоном своей группы обнаружены отличия хешей этапов. Это число парных сравнений, не число уникальных вопросов. Все четыре индекса имеют одинаковые SHA256 для 773 пар chunk ID / embedding. Для 199 повторившихся одинаковых входов к провайдеру в same-index и 198 в fresh-index различий выходов не наблюдалось. Первые расхождения локализованы на этапе поиска, до грейдинга LLM.

Обнаружено повторное upsert всех сохранённых векторов при каждом старте, способное менять HNSW-граф, и отсутствие явного порядка равных кандидатов до отсечения. Внесено общее исправление восстановления/ранжирования; эталонные вопросы, ожидаемые ответы и критерии оценки не менялись. Исправление проверено отдельной полной серией с теми же моделями/данными/параметрами. Профили отличаются только `codeSha256`.

## Полная серия после исправления

[Сводка](after/summary.md), [все попытки](after/series.json), [диагностика](after/analysis.json), [профиль](after/profile.json).

| Измерение | До исправления | После исправления |
|---|---|---|
| Один persistent-индекс, 5 запусков | 18/21 × 5 | 18/21 × 5 |
| Новый индекс, 3 запуска | 18/21 × 3 | 18/21 × 3 |
| Первые десять, каждый запуск | 10/10 | 10/10 |
| Privacy, все 168 ответов | 168/168 | 168/168 |
| Отличающиеся сравнения с первым запуском, из 147 | 26 | 0 |

Сравниваются хеши этапов поиска, выбранных источников, ответов и входов/выходов провайдера; случайные `responseRef` исключены. Все восемь запусков после исправления совпали и между группами, а не только внутри каждой группы. Это наблюдаемое совпадение за конечную серию, а не гарантия детерминизма. Для каждой группы после исправления обнаружено 196 повторявшихся одинаковых входов провайдера и ноль вариантов выхода при одинаковом входе. Во всех восьми индексах двух серий совпали 773 сохранённых embedding-вектора.

Не прошли `overview-01`, `negation-01`, `conflict-01`: по 0/8 до и после. Текущий результат качества — **18/21**, не 21/21; устойчивые ошибки не считаются успешными ответами. Вопросы и критерии PASS не изменялись, неудачные попытки сохранены.

Исправление не перезаписывает уже восстановленные векторы при старте и задаёт порядок равных кандидатов до отсечения. Для небольшого MVP поиск запрашивает расстояния всех допустимых чанков, затем сортирует по distance/ID. Это увеличивает стоимость поиска с ростом корпуса; масштабирование на большие архивы отдельно не проверялось. Наблюдение локализует нестабильность исходной серии в поиске, но два изменения проверены вместе и не разделяют вклад каждого.

## Границы вывода

Это измерение на одном Docker/CUDA-стенде, не гарантия на CPU/Mac или при другой модели. Постоянные 18/21 означают три остающиеся ошибки качества. Фиксированный seed не заменяет измерение. `same-index` включает повторный старт процесса и штатное восстановление persistent-индекса, а не удержание одного графа в памяти. Hash-диагностика локализует различие, но сама по себе не устанавливает универсальную причину расхождений на других машинах.
