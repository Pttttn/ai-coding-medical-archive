# Source IR и baseline ingestion — первый рабочий срез

Техническая запись AI, 25 сентября 2026. Реализация: `fa31c6d`. Это начало P0/P1, не завершение всей подсистемы обработки.

## Реализовано

- `source-ir-v1`: исходные страницы, абзацные блоки, UTF-8 byte spans, компактная карта нормализации пробелов, source hash и hash всего IR. Исходные значения, отрицания, переносы и символы остаются в raw pages; нормализованное представление хранится отдельно.
- Общая JSON Schema и синтетический cross-language fixture в `contracts/`; Python и TypeScript проверяют целостность и границы UTF-8.
- Приватный `/internal/process` возвращает `sourceIR`; backend проверяет его до записи фактов. Поле опционально для переходной совместимости с прежним AI-сервисом; старый ответ не получает фиктивного IR.
- Явная миграция `SourceIR1751000000000`: `source_ir_revisions` с привязкой к неизменяемой TextRevision; UPDATE запрещён триггером, одинаковый `(textRevisionId, irHash)` не дублируется.
- Если текст не изменился, но привязка к страницам изменилась, создаётся новая TextRevision. Старые ссылки остаются на прежней странице/версии.
- `GET /api/documents/:id/source-ir` возвращает исходный IR текущей версии текста; для legacy-документа без IR — 404 `SOURCE_IR_UNAVAILABLE`. Удалённые документы недоступны. Публичный MCP не получает этот маршрут или данные.

Стадия явно называется **SOURCE_ONLY**. IR пока сохраняется после успешного `/process`; модельный сбой до ответа не создаёт отдельного persisted parse checkpoint. Медицинские аннотации, нормализованные лабораторные поля, сохранение стадий до LLM, facts/chunks как проекции IR и согласованная активация остаются дальнейшими задачами P1–P3. Текущий extractor и поиск не заменены новыми алгоритмами.

## Baseline обычной загрузки

`evaluate_ingestion.py` работает только с пустым отдельным архивом, включая корзину; output существующей попытки не перезаписывается. Он загружает шесть исходных PDF через upload и 26 исходных MD через создание текстовой записи. Ни даты/типы из эталона, ни предвычисленные факты модели не передаются. Для текста используется существующий NOTE API, а не фиктивная поддержка MD multipart-upload.

На отдельном Compose `ingestion-p0`, `SEED_ENABLED=false`, host Ollama / Qwen 3.5 9B:

| Проверка | Результат |
| --- | --- |
| Документы | 32/32 READY |
| Source IR | 32/32 сохранены |
| Извлечённые факты | 140 |
| Цитаты найдены в исходном тексте | 140/140 |
| Строгое сопоставление с частичным development gold | **30/108** |
| Сумма времени обработки документов и опроса | 213.04 секунды |

[Полные безопасные агрегаты](ingestion-baseline-summary.json) содержат хеши оригиналов, recipe модели/парсера, исходы каждого документа и ограничения. Содержательные runtime-ответы не включены.

Оценщик использует один-к-одному сопоставление по перекрытию исходной цитаты, типу, assertion и явно заданным valueNumber/unit. Он **не измеряет медицинскую precision/recall полного tuple**: эталон из существующего synthetic seed частичный, новые правильные факты могут не иметь пары. Это известный development-набор, один прогон, не held-out и не оценка переносимости.

После прогона отдельно проверены поля шести лабораторных PDF: из 42 фактов 35 получили `OBSERVATION` вместо `LAB_RESULT`, а 7 фактов `LAB_RESULT` имели пустой `valueNumber`. Эти наблюдения не меняют правила/числа исходного оценщика. Они показывают, почему прошлые QA 10/10 по подготовленному архиву не подтверждают качество ingestion. Простого наличия верной цитаты недостаточно для типизированных tools.

## Воспроизведение

Используйте отдельный новый Compose project и новые тома. Для host-профиля Ollama заранее должны быть доступны `qwen3.5:9b` и `nomic-embed-text`. Создайте `.env.ingestion` по `.env.example`, задав:

```dotenv
COMPOSE_PROJECT_NAME=ingestion-check
SEED_ENABLED=false
LLM_MODEL=qwen3.5:9b
UI_PORT=18080
API_PORT=13001
MCP_PORT=18002
```

```sh
docker compose --env-file .env.ingestion -f compose.yaml -f compose.host-ollama.yaml up -d --build
# Дождитесь healthy backend/ai/gateway и HTTP 200 /api/health.
python scripts/evaluate_ingestion.py --base http://127.0.0.1:13001 --output .local-evaluation/ingestion-first.json
```

Python должен быть из окружения проекта. Результат содержит только агрегаты; новые JSON-файлы автоматически не публикуются. Повтор оценки требует другого пустого Compose project/томов и нового output. Не очищайте личную БД ради запуска теста. Скрипт не удаляет загруженные документы, они остаются для локальной проверки. Первый локальный вызов был сделан до готовности gateway и завершился ConnectionRefused до загрузки документов; baseline запущен после healthy.

## Проверки реализации

Backend: lint/build и **60 tests passed** с отдельной PostgreSQL, включая миграцию существующей БД, неизменяемость IR, идемпотентность reprocess, изменившуюся пагинацию источника и закрытие выдачи удалённого документа. AI: ruff и **207 passed / 2 Windows platform skips**. Первоначальный полный AI-run имел один WinError 10053 в старом loopback shim-тесте; точечный повтор и последующий полный run прошли. Это сохранённая неудача проверки, а не ошибочно объявленный успешным первый запуск. Mock/contract tests отделены от реального ingestion выше.

## Следующее

P0 остаётся открытым для независимых историй/шаблонов и held-out gold. P1 — для полного recipe и сохранения отдельных стадий; P2 — типизированные LAB_REPORT/VISIT, per-field provenance, статусы/даты/референсы. После этого повторить оценку на заранее зафиксированном наборе, затем связать facts и chunks одним IR и проверять активацию (P3). Не повышать статус продукта до готового по одному этому прогону.
