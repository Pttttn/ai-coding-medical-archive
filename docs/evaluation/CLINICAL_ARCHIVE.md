# Клинический архив: протокол оценки

Это фактическая техническая запись AI. Новый сценарий не заменяет прежний публичный MCP21 и не использует его проценты как оценку кабинета.

## Набор и критерии

Один синтетический пациент, 32 документа 2024–2026, 37 индексированных фрагментов с пятью явно помеченными коррекциями. 10 вопросов включают хронические заболевания, подозрение и последующее уточнение диабета, липиды, лабораторные отклонения за год, травмы головы, метформин, неизвестный аллергологический анамнез, отсутствующую операцию и две исходные короткие формулировки пользователя. Эталон `evaluation/clinical_questions.json` не индексируется и не передаётся модели.

Проверяется наличие необходимых сведений, правильный отказ, источники из разрешённого набора; для лабораторных обзоров — **все 19 повышенных результатов за период / 22 за всю историю**, целые строки с единицами и референсами и соответствующие документы. Это необходимые автоматические критерии, а не доказательство полной медицинской корректности. Избыточные цитаты и все возможные противоречия этим набором не измеряются. Ответы требуют просмотра человеком.

`evidencePass` — прохождение указанных содержательных критериев. `coverageComplete` — весь доступный материал просмотрен без окончательных ошибок валидации. `passed` требует обоих условий. Top-12 закономерно может найти ответ при неполном охвате, поэтому в сравнении эти показатели разделены. Для отсутствующего события обоснованность отказа особенно зависит от охвата.

## Два разных вида эксперимента

1. `scripts/evaluate_clinical.py` вызывает **настоящий API приложения**, отказывается работать с личным/смешанным архивом, проверяет ровно READY clinical seed и сохраняет каждую попытку. Повторы оценивают устойчивость одной установки, не переносимость на другой компьютер.
2. `scripts/evaluate_clinical_matrix.py` использует **настоящий локальный Ollama и движок**, но отдельный синтетический индекс и детерминированные IDs коррекций, без API/UI. Это исследовательское сравнение, не замена проверке развёрнутого приложения.

Методы матрицы:

- `scan`: BM25+dense/RRF, затем обзор всех доступных фрагментов (до 120).
- `hybrid12`: первые 12 по BM25+dense/RRF.
- `bm2512`: первые 12 по BM25.
- `dense12`: первые 12 по векторному сходству.
- `tools`: настоящий Ollama function calling; локальные `search_archive` и `read_documents`, до 6 раундов / 12 вызовов, только документы выбранного периода. После поиска ответ проходит тот же проверяющий цитаты движок. Инструменты экспериментальные, не добавлены в публичный MCP.

Параметры фиксируются: температура 0, seed 42, контекст 16384, бюджет цитат 4096 токенов, пакеты до 6 фрагментов, дата 2026-09-24. Сохраняются digest моделей, хеши эталона/набора/движка, объём охвата и длительность каждого вопроса. Первая загрузка модели входит во время; сравнение скоростей на рабочей машине с другими GPU-задачами ориентировочное.

## Команды

Из корня репозитория после установки Python-зависимостей AI-сервиса (команды в README), запущенного host Ollama и наличия выбранных моделей:

```sh
python scripts/evaluate_clinical.py --base http://127.0.0.1:3000/api --runs 3 --output .local-evaluation/clinical-api.json
python scripts/evaluate_clinical_matrix.py --models qwen3.5:2b qwen3.5:4b qwen3.5:9b qwen3.5:27b --strategies scan hybrid12 --runs 1 --output .local-evaluation/clinical-screening.json
python scripts/evaluate_clinical_matrix.py --models qwen3.5:9b --strategies bm2512 dense12 tools --runs 1 --output .local-evaluation/clinical-search.json
```

Первичный отсев по одному прогону показывает направления, но не устойчивость. Для перспективных сочетаний повторите с `--runs 3` и новым именем результата. Повтор того же имени матрицы запрещён: неудачи не перезаписываются. Не запускайте несколько GPU-оценок одновременно. 27B может частично работать на CPU при недостатке VRAM; размер модели не гарантирует полноту извлечения.

Полные ответы остаются в игнорируемом локальном каталоге. В Git публикуются только агрегаты и описание наблюдений, без содержательных runtime logs.

## Результаты текущей работы

API на Qwen 3.5 9B Q4_K_M / RTX 5080: после исправлений **8/8 × 3**, затем исходные короткие вопросы **2/2 × 3**. Все десять вопросов проверены трижды; это две последовательные серии, а не три общих перемешанных прогона. До исправления восстановления цитат две серии дали **7/8 × 3** каждая: нужные факты о диабете были найдены, но один пакет оставался непроверенным. Эти неудачи сохранены в агрегатах.

[Агрегаты API](clinical-api-summary.json) содержат все попытки, охват, длительности и хеши ответов. Полные локальные ответы в Git не включены. Автотесты: AI 188 passed + 2 platform skips до добавления исследовательских проверок; backend 51; frontend 23. Новые точечные AI-проверки 19 passed. Финальный CI фиксируется отдельно.

Свежие тома Compose: 32 READY, 0 pending, 0 failed, 108 фактов; скачивание 32/32 оригиналов побайтно совпадает с fixtures. Шесть PDF отрендерены и просмотрены. Browser smoke: 15 экранов, 0 JS errors, 0 внешних запросов; дополнительно проверены поля периода и отображение фактического API-ответа на desktop/mobile (в UI-тесте ответ воспроизводился из записи, без повторной генерации).

Матрица моделей и методов выполняется; результаты будут добавлены после завершения. Её незавершённые профили не считаются пройденными.
