# Клинический архив: протокол оценки

Это фактическая техническая запись AI. Новый сценарий не заменяет прежний публичный MCP21 и не использует его проценты как оценку кабинета.

## Набор и критерии

Один синтетический пациент, 32 документа 2024–2026, 37 индексированных фрагментов с пятью явно помеченными коррекциями. 10 вопросов включают хронические заболевания, подозрение и последующее уточнение диабета, липиды, лабораторные отклонения за год, травмы головы, метформин, неизвестный аллергологический анамнез, отсутствующую операцию и две исходные короткие формулировки пользователя. Эталон `evaluation/clinical_questions.json` не индексируется и не передаётся модели.

Проверяется наличие необходимых сведений, правильный отказ, источники из разрешённого набора; для лабораторных обзоров — **все 19 повышенных результатов за период / 22 за всю историю**, целые строки с единицами и референсами и соответствующие документы. Это необходимые автоматические критерии, а не доказательство полной медицинской корректности. Избыточные цитаты и все возможные противоречия этим набором не измеряются. Ответы требуют просмотра человеком.

`evidencePass` — прохождение указанных содержательных критериев. `coverageComplete` — весь доступный материал просмотрен без окончательных ошибок валидации. `passed` требует обоих условий. Top-12 закономерно может найти ответ при неполном охвате, поэтому в сравнении эти показатели разделены. Для отсутствующего события обоснованность отказа особенно зависит от охвата.

## Два разных вида эксперимента

1. `scripts/evaluate_clinical.py` вызывает **настоящий API приложения**, отказывается работать с личным/смешанным архивом, проверяет ровно READY clinical seed и сохраняет каждую попытку. Повторы оценивают устойчивость одной установки, не переносимость на другой компьютер.
2. `scripts/evaluate_clinical_matrix.py` использует **настоящий локальный Ollama и движок**, но отдельный синтетический индекс и детерминированные IDs коррекций, без API/UI. Это исследовательское сравнение, не замена проверке развёрнутого приложения.

Методы матрицы:

- `scan`: BM25+dense/RRF, затем обзор всех доступных фрагментов (до 120).
- `hybrid12`: первые 12 по BM25+dense/RRF.
- `bm2512`: первые 12 по BM25.
- `dense12`: первые 12 по векторному сходству.
- `tools`: настоящий Ollama function calling; локальные `search_archive` и `read_documents`, до 6 раундов / 12 вызовов, только документы выбранного периода. После поиска ответ проходит тот же проверяющий цитаты движок. Инструменты экспериментальные, не добавлены в публичный MCP.

Параметры фиксируются: температура 0, seed 42, контекст 16384, бюджет цитат 4096 токенов, пакеты до 6 фрагментов, дата 2026-09-24. Сохраняются digest моделей, хеши эталона/набора/движка, объём охвата и длительность каждого вопроса. Первая загрузка модели входит во время; сравнение скоростей на рабочей машине с другими GPU-задачами ориентировочное.

## Команды

Из корня репозитория с активированным окружением `ai-service/.venv` (либо укажите полный путь к его Python), запущенного host Ollama и наличия выбранных моделей:

```sh
python scripts/evaluate_clinical.py --base http://127.0.0.1:3000/api --runs 3 --output .local-evaluation/clinical-api.json
python scripts/evaluate_clinical_matrix.py --models qwen3.5:2b qwen3.5:4b qwen3.5:9b qwen3.5:27b --strategies scan hybrid12 --runs 1 --output .local-evaluation/clinical-screening.json
python scripts/evaluate_clinical_matrix.py --models qwen3.5:9b --strategies bm2512 dense12 tools --runs 1 --output .local-evaluation/clinical-search.json
```

Для публикации только агрегатов:

```sh
python scripts/analyze_clinical.py .local-evaluation/clinical-screening.json .local-evaluation/clinical-search.json --output docs/evaluation/clinical-matrix-summary.json
```

Первичный отсев по одному прогону показывает направления, но не устойчивость. Для перспективных сочетаний повторите с `--runs 3` и новым именем результата. Для проверки повторного построения добавьте `--fresh-index-per-run`: для каждого прогона создаётся новый отдельный синтетический индекс, существующие индексы не удаляются. Повтор того же имени результата запрещён: неудачи не перезаписываются. Не запускайте несколько оценок на одном GPU одновременно. Для поддерживающих thinking моделей доступен явный `--no-thinking`; он фиксируется в отчёте. Без флага действует поведение провайдера (для Qwen thinking отключён, для других моделей — серверное умолчание). 27B может частично работать на CPU при недостатке VRAM; размер модели не гарантирует полноту извлечения.

Полные ответы остаются в игнорируемом локальном каталоге. В Git публикуются только агрегаты и описание наблюдений, без содержательных runtime logs.

## Результаты текущей работы

API на Qwen 3.5 9B Q4_K_M / RTX 5080: после исправлений **8/8 × 3**, затем исходные короткие вопросы **2/2 × 3**. Все десять вопросов проверены трижды; это две последовательные серии, а не три общих перемешанных прогона. До исправления восстановления цитат две серии дали **7/8 × 3** каждая: нужные факты о диабете были найдены, но один пакет оставался непроверенным. Эти неудачи сохранены в агрегатах.

[Агрегаты API](clinical-api-summary.json) содержат все попытки, охват, длительности и хеши ответов: во всех десяти случаях текст совпал в трёх повторах соответствующей серии. Полные локальные ответы в Git не включены. Автотесты: GitHub Linux CI для `860c714`: **AI 193, backend 51, frontend 23**, без skips; lint и Docker images PASS. [Run](https://github.com/ruslan-yusupov-open/ai-coding-medical-archive/actions/runs/36057524841). Финальный код стенда `0252f98`: **AI 196, backend 51, frontend 23**, Linux CI без skips, lint/images PASS. [Run](https://github.com/ruslan-yusupov-open/ai-coding-medical-archive/actions/runs/36061598387). Локальный Windows-запуск до последнего дополнительного теста: 193 passed / 2 platform skips; не смешивается с Linux-счётчиком.

Свежие тома Compose: 32 READY, 0 pending, 0 failed, 108 фактов; скачивание 32/32 оригиналов побайтно совпадает с fixtures. Шесть PDF отрендерены и просмотрены. Browser smoke: 15 экранов, 0 JS errors, 0 внешних запросов; дополнительно проверены поля периода и отображение фактического API-ответа на desktop/mobile (в UI-тесте ответ воспроизводился из записи, без повторной генерации).

### Первичный отсев и устойчивость

Полный обзор: Qwen 3.5 2B — **8/10**, 4B и 9B — **10/10** в первичном одиночном прогоне. 2B не нашла документальное отрицание приёма метформина и неверно выбрала цитату для неизвестного аллергологического анамнеза. Проверка дословности цитаты сама по себе не гарантирует её релевантность вопросу.

На 9B стратегии top-12 дали: **RRF 8/10, BM25 8/10, dense 7/10, tools 8/10** по содержанию. Все имеют неполный охват. Во всех четырёх вариантах провалены оба обзора лабораторных отклонений; dense дополнительно не прошёл метформин. В tools годовой обзор завершился ошибкой ValueError планирования, общий обзор пропустил строки. Лимит tools: 6 раундов / 12 вызовов, 768 токенов плана; эти результаты относятся именно к такому ограниченному агенту. Увеличение бюджета не проверялось.

Серверная Q8 27B / llama.cpp: **10/10 × 3** с новым индексом в каждом прогоне. Все десять текстов побайтно совпали между тремя повторами. Суммарное время десяти вопросов: 220.15 / 221.07 / 219.98 секунд; отдельный ответ 12.06–34.48 секунды. Это перенос генерации на другой сервер; индекс и embeddings оставались на Windows, поэтому не заявляется независимое Docker-развёртывание всего приложения.

Локальная Qwen 3.5 27B Q4 с частичным CPU offload: **5/5 завершённых вопросов**, 126.7–425.34 секунды на ответ; затем профиль намеренно остановлен из-за задержки. Остальные пять и hybrid12 не выполнены; **10/10 не заявляется**. Gemma 12B с thinking по умолчанию остановлена до завершения первого вопроса; оценка качества для этого режима отсутствует. Оба незавершённых эксперимента сохраняются в агрегатах.

На той же серверной Q8 27B ограничение RRF top-12 даёт **8/10**, оба лабораторных обзора не проходят. Большая модель не восстановила отсутствующие в выборке строки.

Qwen 3.5 4B / Ollama / Q4_K_M: **10/10 × 3**, каждый раз новый индекс (32 документа / 37 фрагментов), все десять текстов совпали между повторами. Явный `--no-thinking`, температура 0, seed 42. Десять вопросов заняли 81.67 / 80.03 / 79.26 секунды. Малую модель нельзя заранее считать непригодной: на этом ограниченном сценарии полный обзор исправил основной недостаток top-12. Устойчивость к другим историям, переформулировкам и шумным PDF этой серией не измерялась.

Gemma 4 12B Q4_K_M с явным `--no-thinking`: **10/10** в одном прогоне, 5.51–25.06 секунды на ответ; устойчивость повторениями для неё не проверялась. Это отдельный режим относительно остановленного запуска с серверным thinking по умолчанию.

[Агрегаты всей матрицы](clinical-matrix-summary.json) содержат все завершённые профили и явные `complete=false` для остановленных. Для top-12 в таблицах используется `evidencePass`; строгий `passed` дополнительно требует полного охвата и потому равен нулю для этих профилей.

Время включает генерацию и накладные расходы, иногда загрузку модели. GPU использовался также embeddings и работающим приложением; это практические наблюдения, а не изолированный скоростной бенчмарк.

## Отдельный сервер llama.cpp через SSH

Для синтетического набора есть `scripts/evaluate_clinical_ssh.py`. Нужны Python 3 на сервере, SSH без интерактивного пароля и локальный Ollama с `nomic-embed-text`. Ключ читается Python-процессом на сервере, не копируется на клиент и не включается в отчёт. Отправляются только fixtures из репозитория; API личного архива адаптер не использует. На Windows доступ через WSL включается флагом `--wsl`; на Linux его опустите.

```sh
python scripts/evaluate_clinical_ssh.py --wsl --ssh-target root@mpc1 --ssh-key-file /etc/llama-q8-64k.keys --ssh-port 11435 --models qwen3.8-27b-q8-100k-cuda --strategies scan --runs 3 --fresh-index-per-run --model-sha256 a680f44a06920e5d689774823782006aa3acc8db95750323373b24139b67e348 --output .local-evaluation/clinical-mpc1.json
```

Замените адрес, путь к ключу, model ID и SHA256 на параметры своей установки. `--model-sha256` — предварительно измеренный хеш GGUF, а не автоматически проверяемая контрольная сумма. Без него идентичность весов неизвестна. Адаптер проверяет model ID через авторизованный `/v1/models`; `/props` сохраняет действительный размер контекста. Поддерживаются scan/BM25/dense/hybrid; перевод диалога tools через SSH пока не реализован и явно отклоняется.

На проверенном mpc1: имя GGUF `Qwen3.8-27B`, архитектура `qwen35`, Q8_0, файл 29 047 086 048 байт; RTX 4090 + RTX 5080, split layer 64/36, GPU layers 99, flash attention on, один slot. Реальный серверный контекст **180224**, а не 16384 из Ollama-профиля; `num_ctx` через этот адаптер не передаётся. Температура 0, seed 42, max_tokens 4096 и `enable_thinking=false` передаются явно. Это сравнение разных установок/весов, не изолированный тест одной лишь разрядности или числа параметров. Alias и имя GGUF описывают установленную модель; её происхождение по этим именам не подтверждается.
