## Рекомендации и принятые инженерные решения

Конспект отдельно характеризует проверку выдачи локальной моделью как настоятельную архитектурную рекомендацию преподавателя, а не единственную допустимую реализацию. Следующие детали являются нашим принятым решением по этой рекомендации.

| Решение | Зачем | Изменение контракта |
|---|---|---|
| Один RAG engine, два жёстко заданных корпуса | Сохраняет общий поиск и исключает выбор личного архива внешним агентом | Внутренний `archive`; публичный MCP только `mcp_demo`, без corpus selector |
| Общие правила и локальная LLM для privacy | Ручная консультация и MCP не получают независимые, расходящиеся механизмы очистки | Общие категории, сохранение полезного содержания и fail-closed |
| Проверяется вся исходящая выдача | Очищенного поля answer недостаточно, если цитата или имя файла содержит идентификатор | Очищаются ответ и фрагменты; произвольные пути/названия/ID/metadata/trace исключены из публичной схемы |
| Непрозрачные `responseRef` и `S1` | Источник остаётся проверяемым локально без раскрытия имени файла или стабильного ID | Свежий responseRef для результата; связь с реальным источником хранится только локально, MCP-tool раскрытия связи нет |
| `find_relevant_docs` тоже проходит privacy | Иначе второй tool обходит очистку готового ответа | Нет предметной генерации/rewrite/grading, но локальная privacy LLM разрешена и обязательна для выдачи фрагментов |
| `index_folder` и `index_status` возвращают агрегаты | Статистика не должна раскрывать исходные имена, пути или ошибки парсера | Только разрешённые счётчики/состояние/параметры chunking; без времён, исходных metadata и генеративной LLM |
| Безопасные ошибки и отказ | Сбой privacy не разрешает выдавать исходный результат | Фиксированные сообщения без echo входа, provider exception и stack trace; fail-closed при model-down/timeout/невалидном ответе |
| Прямой запрос идентификатора не меняет политику | Проверяется настоящая граница, а не только удобные вопросы | ФИО, номер карты, контакт не выдаются через ask, find, metadata или ошибки |
| Синтетика с вымышленными идентификаторами | Даёт наблюдаемую проверку очистки вместо заранее обезличенного корпуса | Отрицательные fixtures включают текст/заголовки/имена файлов с искусственными идентификаторами |
| Контрольные факты из разрешённого содержания | Код документа может корректно удаляться как идентификатор | Проверяются числа с единицами, интервалы, дозы, рекомендации, отрицания и неизвестность приёма |
| Предметные chunking-тесты | Размер чанка сам по себе не доказывает сохранение смысла | Анализ + значение + единица; препарат + доза; рекомендация + срок; утверждение + отрицание |

Текущий corpus manifest описывает 42 файла и 663711 файловых байт. Нижнюю границу 512000 подтверждает отдельно текст TXT/MD — 661410 байт; бинарный размер PDF для этого не нужен.

Примеры положительных фактов — сведения о том, **что записано в синтетическом документе**. Они не подтверждают медицинскую правильность вымышленных рекомендаций. Прохождение privacy-набора не является доказательством полной анонимности.

## Сохранённые продуктовые границы

Кабинет, CRUD, факты и immutable provenance, пользовательские поправки, история, timeline, dashboard и Ask Archive сохраняются. Для личной консультации остаются точный preview, ручное подтверждение content hash и Copy/Markdown; любая правка сбрасывает review. Автоматическая проверка дополняет ручной просмотр.

MCP автоматически отвечает подключённому хосту по синтетическому корпусу. Это передача данных, даже если сам сервер не использует внешний AI API. Поэтому утверждение «любые данные покидают систему только через ручной Copy» не используется. Доступ MCP к личному архиву не появляется.

SDK внешней модели, ключи провайдера, внешний LLM-gateway и автоматическая отправка консультаций не добавляются. Уже существующие локальные nginx ingress и фиксированный host-Ollama proxy решают сетевую задачу и не являются таким внешним AI-шлюзом. OCR, изображения, диагнозы, новые медицинские tools, сложная онтология, multi-user и смена стека не входят в изменение.

## Как подтвердить реализацию

Нужны отдельные доказательства для изменённого контракта: parser/chunking/схема/ошибки в детерминированных тестах; настоящий MCP transport; privacy и полезность на реальном Ollama; выбор tool host-агентом без подсказки; точный ручной review/export. Старые оценки на кодах записей и сырых источниках относятся к v1.1 и не подтверждают v1.2 автоматически.

Результаты, неудачи и ограничения фиксируются в `docs/evaluation/` и VALIDATION. Этот документ не содержит заявления о новых пройденных тестах. Личный анализ процесса в REPORT автор пишет самостоятельно; AI-записи остаются явно помеченными.
