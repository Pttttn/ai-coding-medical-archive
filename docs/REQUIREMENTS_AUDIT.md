# Аудит требований и запуска с нуля

Техническая AI-запись от 19 сентября 2026. Это проверка реализации и доказательств, а не решение преподавателя о приёмке.

## Вывод

Основные технические требования двух заданий реализованы. Проверен настоящий чистый клон: без `.env`, установленных в клоне зависимостей, готовой БД, индексов или весов. Docker самостоятельно собрал приложение, скачал обе модели, выполнил миграции и seed. Проверки использовали контейнерный CPU Ollama, без host Ollama и без mock-моделей.

Полную формальную готовность к сдаче пока объявлять нельзя: личная часть REPORT не заполнена, подтверждения принятия собственной темы нет, демонстрация в конкретной IDE пользователя ещё не выполнена. Кроме того, реальный расширенный RAG-набор имеет четыре известных неудачных случая. Эти ограничения не скрыты успешными Docker или unit-тестами.

## Протокол чистого запуска

Исходная опубликованная ревизия: **4680ced**. Клон выполнен с GitHub в новую пустую папку. До запуска отсутствовали контейнеры и тома проекта `lma-cold-20260919`. Локальный `.env`, node_modules, Python venv, данные и веса из рабочего экземпляра не копировались. Сборка происходила внутри Docker.

Среда: Windows/Docker Desktop, Linux Engine 29.7.2, Compose 5.4.0, около 64 ГБ RAM доступно Docker. Использован CPU внутри контейнера; GPU и host Ollama не подключались. Это **чистые приложение и тома на уже установленном Docker**, а не новая ОС: базовые Docker-образы и часть BuildKit cache уже были на машине. Работа на минимальной RAM, Linux ARM и rootless Docker отдельно не проверялась.

Рабочий экземпляр и чужие сервисы оставались запущенными. Поэтому только имя проекта и опубликованные порты переопределены; стандартный Compose и его модели не заменялись:

```powershell
$env:UI_PORT = '18080'
$env:API_PORT = '18000'
$env:MCP_PORT = '18002'
docker compose -p lma-cold-20260919 up -d --wait --wait-timeout 1800
```

Для обычной свободной машины эти переменные и `-p` не требуются. Отдельного `build`, `npm install`, `uv sync`, `ollama pull`, запуска генератора seed или ручной миграции в клоне не было. Python/Playwright вне клона использовались только как тестовые клиенты после старта.

Первый запуск начат около 13:08 UTC; контейнер `model-init` работал **13:09:04–13:10:18 UTC**, автоматически скачал обе модели и завершился с кодом 0. Seed создан около 13:10:38 UTC; при наблюдении 13:11:12 UTC было 34/36 READY, затем все 36 стали READY без ошибок. Время не является benchmark или гарантией для другой сети/CPU.

## Исправления по аудиту

1. README теперь начинается с полного `git clone` → `cd` → `docker compose up`. Разделены готовность сервисов, окончание seed-индексации и изначально пустой MCP; описаны одноразовый model-init, порты, остановка и повторный запуск.
2. AI healthcheck проверяет именно `ready=true`. Ранее HTTP 200 мог скрывать недоступность Ollama/весов. Проверка выполнена с реальной остановкой и восстановлением Ollama только в тестовом проекте.
3. Gateway ждёт healthy у upstream и имеет собственный HTTP healthcheck UI/API. `--wait` больше не полагается только на состояние running у внешней точки входа.
4. `runtime_check.py --project` позволяет проверять отдельный экземпляр и не обращаться случайно к рабочему Compose-проекту.
