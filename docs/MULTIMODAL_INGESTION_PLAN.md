# Согласование источников для лабораторных документов

Технический план AI, 25 сентября 2026. Это развитие отдельного Medical Document Processing Pipeline, а не изменение учебной спецификации v1.2 и не утверждение клинической готовности.

## Каналы и происхождение

1. **Текстовый слой PDF** даёт строки, порядок колонок и текстовые координаты. Он может быть исходным цифровым текстом или уже встроенным результатом OCR. Пока происхождение не установлено как `NATIVE`, его нельзя считать независимым от локального OCR.
2. **OCR по пикселям страницы** должен вернуть текст, координаты ячеек, confidence, версию движка и привязку к странице/области. Это будущий адаптер; сейчас приложение возвращает `UNSUPPORTED_OCR_REQUIRED` для PDF без текстового слоя.
3. **Визуальная модель по пикселям** читает ту же область, не получая ячеек парсера или OCR в prompt. Уже есть read-only лабораторный evaluator. Его результат пока не записывается в факты.

Все каналы сохраняют ссылку на один неизменяемый оригинал и конкретную страницу/область. Таблицы надо сначала выровнять по геометрии и строкам; при разных количествах строк нет позиционного сравнения «строка N со строкой N». Согласование выполняется **по полям**: название, результат со знаком сравнения, единица, референс, позже дата/роль. Нормализуются только пробелы; десятичные знаки, числа, единицы, отрицания и границы референса не «исправляются» большинством.

## Политика решения

| Наблюдение | Решение | Действие |
| --- | --- | --- |
| Три различных метода совпали по всем полям, цифровой текстовый слой подтверждён как `NATIVE` | `CONSISTENT_3` | Свидетельства согласованы; это не доказательство медицинской правильности и не автоматическое принятие факта. |
| Совпали только два метода; третий недоступен, в том числе OCR + vision для скана | `REVIEW_INSUFFICIENT` | Показать кандидата и оригинал для ручной сверки. |
| Два метода против одного либо три разных значения | `REVIEW_CONFLICT` | Не выбирать большинство, особенно для результата, знака, единицы, дозы и даты. |
| Не совпали строки/границы таблицы | `REVIEW_ALIGNMENT` | Остановить сравнение полей по индексам и проверить layout. |
| Ошибка метода, пустая страница, недостоверное происхождение OCR-слоя | review/unsupported | Не делать raw fallback и не создавать подтверждённый факт. |

Несколько запусков одной модели показывают **устойчивость**, но не становятся отдельными голосами. OCR и visual model, работающие по одним пикселям, тоже могут ошибаться одинаково; `CONSISTENT_3` означает согласованность каналов, не независимый human gold. Для смешанного PDF маршрут выбирается по каждой странице, а не по одному признаку наличия текста во всём файле.

## Реализованный первый шаг и следующий этап

`medical_ai.lab_consensus.reconcile_lab_rows` реализует безопасное согласование полей без выбора значения и без вывода медицинского текста. Текущий `vision_audit` включает `evidenceDecision` в отчёт: совпадение PDF-парсера с vision пока даёт `REVIEW_INSUFFICIENT`, поскольку OCR-канала нет. Это read-only проверка; ingestion и БД не меняются.

Следующий отдельный этап: выбрать и проверить **локальный** OCR-движок на синтетических цифровых, сканированных и смешанных PDF; сохранить bounding boxes и версии в IR, разработать выравнивание таблиц и review UI. До подключения в ingestion нужны замороженный held-out набор, ручная разметка критичных полей, измерение false agreement/FP/FN по трём запускам и тесты чистого Docker Compose. Для сканов OCR + vision без цифрового текстового канала остаются кандидатами на ручную проверку, а не автоматически подтверждёнными фактами.
