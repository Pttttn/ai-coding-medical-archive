# Structured tools, локальный агент и Medical Reference Library — следующий этап

Дата: 2026-09-25. **План, не описание реализованных функций.** Приоритет — [Medical Document Processing Pipeline](MEDICAL_DOCUMENT_PIPELINE_PLAN.md). Основание: три пользовательских конспекта о предметных tools, двух источниках знаний и открытых справочниках. Формальные требования учебного MVP v1.2 не расширяются задним числом.

## 1. Разделение обязанностей

| Вопрос | Первый путь | Обязательная оговорка результата |
| --- | --- | --- |
| Последний LDL, динамика, отклонения за период | Типизированные данные PostgreSQL | Дата/роль, единицы, референс бланка, покрытие извлечения |
| Что написал невролог, какие были рекомендации | BM25 + dense/RRF + Corrective RAG по архиву | Проверенные исходные цитаты, период и охват |
| Какие лекарства принимает сейчас | История medication events | Последнее документированное состояние на дату; давняя запись не доказательство текущего приёма |
| Подозревали ли диабет, подтвердили ли | История condition assertions + source access | Не смешивать suspicion, not confirmed, ruled out, family и patient |
| Анализы и жалобы после начала лекарства | Несколько bounded tools + RAG | Временная последовательность не доказывает причинность |
| Для чего обычно используют препарат | Отдельный reference retrieval | Справочная информация, не факт о пациенте |

Не подменять RAG свободным SQL/shell-агентом. Начать с детерминированной маршрутизации явных числовых/документных запросов; для неоднозначных запросов использовать ограниченную классификацию с проверяемой схемой и fallback к уточнению/обзору, а не уверенный неверный route. В сложных вопросах агент составляет план разрешённых операций, но не получает SQL, файловую систему или произвольную сеть.

Наш эксперимент с `tools` был поисковым агентом с `search_archive/read_documents`, а не доступом к качественной типизированной БД. Его 8/10 не измеряет предложенную архитектуру structured tools. Большая модель с top-12 также пропускала лабораторные строки; сначала нужно дать tools полный проверяемый набор наблюдений.

## 2. Предметные инструменты внутри приложения

Предлагаемые инструменты, все read-only:

- `get_lab_history(test, from, to, dateRole, cursor)` — все подходящие наблюдения, безопасная сортировка, оригинальные единицы/референсы и группы совместимости; без умолчального top-k на медицинские строки.
- `get_medication_history(name, asOf, cursor)` — события назначения/приёма/отмены с источниками; поле `current` не выводится из одного старого назначения.
- `get_conditions(subject, assertion, from, to, cursor)` — документированные утверждения, без автоматического диагноза по лабораторному порогу.
- `get_timeline(from, to, cursor)` — медицинские события с ролью/точностью даты.
- `search_patient_documents(query, filters, cursor)` — RAG только по разрешённому snapshot архива.
- `get_source_excerpt(sourceRef)` — ограниченный span уже разрешённого документа/revision; не произвольный путь или file ID.
- `search_medical_reference(query, filters, cursor)` и `get_reference_section(referenceRef)` — только по отдельной локальной справочной коллекции.

Каждый tool возвращает `snapshot`, `items`, `sources`, `coverage`, `warnings`, `nextCursor`. Coverage включает число подходящих документов/строк, качество extraction и неполную пагинацию. Агент обязан дочитать страницы либо назвать ответ частичным; пагинация не должна незаметно превращаться в top-12. Все вызовы привязаны к одному разрешённому snapshot, включая review revision; изменение исходника не смешивает старый и новый ответ.

Первый бюджет агента: до 6 раундов / 12 вызовов, разрешённые arguments со строгими схемами, ограничение размера возвращаемого контекста и общий timeout. Бюджет — экспериментальная настройка, а не обещание качества: его исчерпание даёт partial coverage. Кэш только по snapshot + нормализованным аргументам, с инвалидированием edit/delete/review. Текст документа/справочника никогда не является инструкцией для выполнения tool.

MCP — внешний интерфейс, а не транспорт для каждого внутреннего вызова. Существующий публичный MCP сохраняет четыре инструмента, неизменяемую границу `mcp_demo` и sanitizer. Новые личные tools автоматически туда не экспортируются.

## 3. Три независимых пространства данных

1. **Patient archive**: личные документы и structured facts, привязанные к processing revision и review overlay.
2. **Medical reference**: общие справочные материалы, собственные source IDs, версии и preprocessing, отдельная Chroma collection/BM25.
3. **Public MCP demo**: прежний фиксированный синтетический корпус. Он не становится шлюзом к двум предыдущим.

Минимум 512000 байт из учебных требований по-прежнему проверяется для существующего демонстрационного MCP-корпуса. Предложение из конспекта о «500 KB patient records» не переносится в обязательные требования личного архива и не оправдывает искусственное дублирование данных.

В UI и answer schema раздельны `patientEvidence` и `medicalReference`. Ссылки используют разные пространства: пациентский документ/страница против title/edition/chapter/section/page/URL справочника. Общая медицинская закономерность не попадает в таблицу patient facts. Справочник не создаёт диагноз, не меняет референс на лабораторном бланке и не подтверждает причинность у пациента.

## 4. Минимальная справочная библиотека

Начать с **2–5 выбранных глав/разделов из 2–3 источников**, относящихся к синтетической истории: липиды, углеводный обмен, лекарства и терминология. Не скачивать целые библиотеки без проверки конкретного материала. В первом прототипе только локальные сохранённые тексты, никакого веб-поиска по содержанию личного вопроса и автоматического обновления источника во время ответа.

Предварительная проверка первичных страниц выполнена 2026-09-25. Это реестр кандидатов; импорт ещё не выполнялся.

| Кандидат | Подтверждено на странице источника | Решение для прототипа |
| --- | --- | --- |
| [Open RN Health Alterations, 2024](https://www.ncbi.nlm.nih.gov/books/NBK613068/) | Указана CC BY 4.0 с исключениями; есть отдельные заимствования и условия для дополнительных материалов | Подобрать несколько текстовых разделов, проверить их исключения/атрибуцию |
| [Open RN Nursing Pharmacology 2e, 2023](https://wtcs.pressbooks.pub/pharmacology2e/front-matter/introduction/) | CC BY 4.0 с исключениями; сам издатель отличает учебник от лекарственного справочника | Общее объяснение классов/действий, не источник персональных дозировок |
| [Open RN Medical Terminology 2e, 2024](https://wtcs.pressbooks.pub/medterm/front-matter/introduction/) | CC BY 4.0 с исключениями | Терминология и проверяемые синонимы; не источник диагнозов |
| [OpenStax Medical-Surgical Nursing](https://openstax.org/books/medical-surgical-nursing/pages/preface) | На странице явно указано требование предварительного письменного разрешения для LLM/generative AI ingestion | Не включать в первоначальный импорт без разрешения/разрешения вопроса условий |

Утверждения конспекта о лицензиях всей NCBI Bookshelf, StatPearls, всех WHO guidelines и DailyMed не считаются общей лицензией на любой документ: для каждого будущего источника отдельная проверка конкретной версии и компонентов. StatPearls, Clinical Methods, WHO и DailyMed остаются кандидатами backlog, не включены в текущую поставку. Мы не принимаем решение о применимости спорных условий лишь по ярлыку Creative Commons.

Manifest источника: title, authors/editor, publisher/organization, sourceType, edition/version, publication/update year, language, jurisdiction, source URL, section IDs, importedAt, contentSha256, license ID/URL, attribution, exclusions, modification/translation notice, licenseCheckedAt, reviewStatus. Иметь состояния active/superseded/withdrawn; старый ответ должен продолжать ссылаться на использованную версию, а новый поиск по умолчанию выбирает одобренную актуальную.

Reference preprocessing сохраняет book → chapter → section → subsection, таблицы, исключения/противопоказания рядом с утверждением и номера страниц, если они доступны. У HTML page может отсутствовать: тогда chapter/section/anchor; номер PDF не выдумывать. Справочный IR использует общий механизм spans/versioning, но не схему patient facts.

Англоязычный учебник не обеспечивает автоматически хороший поиск русских вопросов. Проверить RU→EN retrieval на отдельном gold-наборе; словарь LDL/ЛПНП и других вариантов хранить с версией. Не объявлять перевод медицински эквивалентным без проверки. Смена embedding-модели требует отдельной переиндексации и измерения, а не тихой подмены существующего пространства векторов.

## 5. Приёмка следующих этапов

- P5: SQL/tools и RAG используют один snapshot. Полная динамика LDL и все отклонения сравниваются с gold; missing/unknown/partial различаются; пагинация проверена на наборе больше лимита одной страницы.
- P5: router оценивается отдельно (ошибки выбора пути), затем end-to-end. При вопросе только об архиве reference search не вызывается.
- P6: сравнить простой router, router + bounded agent и прежний archive scan на одном замороженном наборе. Новая обвязка принимается только при измеримом выигрыше качества/полноты или времени, а не из-за наличия tool calls.
- P6: тесты patient/reference separation, версия/атрибуция каждой справочной цитаты, отказ при отсутствии источника, prompt injection, невозможность доступа из публичного MCP. Учебный фрагмент о диабете не должен превращаться в диагноз пациента.
- P6: кейс «после начала аторвастатина: динамика LDL и документированные жалобы» объединяет три источника данных, но не делает причинный вывод. Неизвестная фактическая дата старта показывается явно.
- Для каждого принятого профиля — три реальные серии, исходы всех попыток, timeout/бюджет/число вызовов, latency, source validity и полнота. Личный REPORT не переписывается; публикуются технические агрегаты.

Первый следующий coding PR должен покрыть **P0 + P1 pipeline**, а не агент/reference library. Так можно проверить качество исходного представления до усложнения ответа.
