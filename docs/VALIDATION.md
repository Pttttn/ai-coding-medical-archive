## Изменения и обнаруженные ошибки

Корпус теперь содержит 42 файла MD/TXT/PDF: 663711 файловых байт, из них 661410 байт обычного индексируемого текста, достаточных для порога 512000 без PDF overhead. Manifest проверен по рабочим файлам и по Git blobs после нормализации LF. Seed по-прежнему 36 записей, неизменяемые источники и 5 исправлений. Реальная миграция MCP-индекса: 45/777 → 42/773 (файлы/чанки), удалены 5 запрещённых форматов. Последующие index_folder ничего не дублируют.

Публичные поля ограничены очищенным текстом, reference S1/S2 и случайным responseRef. Локальная таблица соответствий не доступна через MCP. Весь сериализованный ответ проверяется, включая ошибки. Проверены недоступность модели, неверный JSON, неизвестные поля, несуществующие spans, числовые коллизии, единицы, даты, отрицания и неизвестность приёма. Цитаты собираются структурно, поэтому медицинские [17]/[1] не превращаются в номера ссылок.

Реальная модель выявила проблемы сверх тестовых адаптеров: подстановка частей имени ломала email до его удаления; имя после fictional participant не очищалось; адрес 15 Pine Street ошибочно считался числом с единицей. Исправлены порядок обработки, общий шаблон narrative name-cue и проверка адресов. Неудачные попытки сохранены: [email](evaluation/v12-public-rag-before-email-order.json), [имя без метки в MCP](evaluation/v12-mcp-http-before-name-cues.json), [ложный отказ адреса](evaluation/v12-manual-privacy-before-address-guard.json). Старые privacyPassed flags отражают набор проверок на момент запуска, а не итоговое отсутствие утечек.

## Известные ограничения

В историческом прогоне v1.2 на qwen2.5:3b не прошли: **overview-01, multi-01, negation-01, conflict-01**. Обзор выбирает слишком узкий источник; вопрос о двух визитах и отдельный вопрос о неизвестном приёме могут получить ложный отказ; противоречие Spruce не подтверждается полным ожидаемым набором источников и блокируется строгой privacy-проверкой. Эти случаи сохранены, а не исключены из знаменателя.

Метрика проверяет заданный текст, нужные источники, ожидаемый отказ и известные вымышленные идентификаторы. Она не измеряет медицинскую правильность и не доказывает полную анонимность. Ручной preview/hash остаётся обязательным для личного экспорта. MCP автоматически передаёт очищенную синтетику host-агенту; доступ к личному корпусу и внешние AI SDK не добавлены.

Новая дата защиты и принятие собственной темы не подтверждены; по авторским записям тема отправлена на утверждение 14 сентября. Личная часть REPORT оформлена по предоставленной автором хронологии и реальным запросам, отдельно от AI-приложений. Reference host действительно использует MCP, но не заменяет проверку конкретного IDE пользователя.

## Техническое дополнение AI: целостность цитат и правок, 25 сентября 2026

Закрыты три находки ревью от 25 сентября, каждая сначала воспроизведена падающим тестом.

## Техническое дополнение AI: privacy-очистка не портит медицинские слова, 26 сентября 2026

Закрыта находка 6 ревью от 25 сентября. Каждый сценарий сначала воспроизведён на прежнем коде.

- Спаны локальной модели заменялись `str.replace` внутри слов: спан «ин» превращал «Метформин» в «Метформ[PERSON_A]». Теперь спан заменяется только целым словом. Спан короче 3 символов, слово из стоп-листа медицинских терминов и эпонимов, спан, встречающийся только внутри слов, и спан через границу двух полей в публичном MCP закрывают выдачу, в ручной консультации оставляются без изменений с предупреждением.
- Части имени заменялись везде и без учёта регистра: врач «Mark Stone» превращал «kidney stone» в «kidney [DOCTOR_A]». Теперь многословное имя заменяется без учёта регистра, отдельная часть — только с заглавной буквы, с учётом регистра и вне стоп-листа. Цена: одиночная фамилия из стоп-листа («Stone») остаётся в тексте.
- ФИО без метки зависело только от модели. Теперь без модели скрываются русские ФИО с отчеством, фамилии с инициалами («Петрова А.С.», «А. С. Петрова») и имена после Dr./Prof./Mr./д-р/проф. Английские «Имя Фамилия» без метки по-прежнему ловит только модель.
