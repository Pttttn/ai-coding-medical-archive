# Full‑Stack приложение, сгенерированное AI с нуля

**Описание:**
Создать full‑stack приложение (backend + frontend + БД), используя AI для генерации архитектуры, кода и инфраструктуры. 
Проект стартует с описания функционала, а не с кода.

**Результаты:**
- Работающее приложение с минимум 4‑5 ключевыми фичами
- Тесты, документация и CI pipeline
- Демо‑развёртывание (Docker-compose, локально)

**Технологии:**
- не ограничено, если сумеете это запаковать в docker compose
- PostgreSQL / SQLite для простоты
- Docker, GitHub Actions

Далее будут представлены несколько вариантов приложений.


## Общие требования для всех вариантов

**Функциональные (базовые):**
- CRUD основных сущностей с валидацией на клиенте и сервере
- Поиск и фильтрация по ключевым полям
- Дашборд с визуализацией данных (графики / статистика)
- Пагинация списков
- Адаптивная вёрстка (desktop + mobile)

**Нефункциональные:**
- Seed‑данные: приложение запускается с реалистичным набором демо‑данных
- REST API с OpenAPI/Swagger документацией (в виде живой веб-страницы, а не доки в проекте)
- Не менее 10 unit/integration тестов
- CI pipeline (GitHub Actions): lint + тесты; сборка Docker‑образа — опционально
- Всё приложение запускается одной командой `docker compose up` (backend + frontend + БД)
- файл README.md инструкцией по запуску (формат - markdown)
- Файл ARCHITECTURE.md с описанием архитектуры и плана разработки (начните с него, формат - markdown)
- (Опционально) Ссылка на видео-демонстрацию работы приложения может упростить и ускорить проверку
- Файл REPORT.md с вашим описанием истории создания проекта, с какими ключевыми проблемами вы столкнулись, как решали. Ваши удачные и неудачные шаги. Добавляйте туда данные по мере работы, не в самом конце. Формат - markdown.
- Проект создан в новом, пустом GIT репозитории. Существует адекватная история коммитов (не всё разом).

### Вариант 1: Трекер личных финансов

Общие требования плюс:

**Функциональные:**
- Транзакции: сумма, дата, категория, описание, тип (доход/расход)
- Справочник категорий (иконки, цвета) с возможностью CRUD
- Месячные бюджеты: установка лимита на категорию, прогресс‑бар расхода
- Дашборд: круговая диаграмма расходов по категориям, линейный график динамики за 6 месяцев, топ‑5 категорий
- Фильтрация транзакций по дате, категории, сумме (от/до)
- Импорт транзакций из CSV‑файла (маппинг колонок при загрузке)
- Экспорт отфильтрованных транзакций в CSV
- Повторяющиеся транзакции (ежемесячные подписки, зарплата) — автосоздание по расписанию
- Мультивалютность: выбор основной валюты, хранение курса на момент транзакции
- Регистрация / авторизация (JWT), два предзаполненных аккаунта (например, личный и семейный); каждый пользователь видит только свои транзакции и бюджеты
- Лог изменений: каждое создание, редактирование и удаление транзакции или бюджета фиксируется с указанием пользователя, времени и значений до/после; журнал доступен для просмотра

**Seed‑данные:** 200+ транзакций за 6 месяцев, 12 категорий, 3 бюджета, 2 пользователя

### Вариант 2: Доска задач (мини‑Trello)

Общие требования плюс:

**Функциональные:**
- Регистрация / авторизация (JWT), два предзаполненных пользователя
- Создание досок (boards), каждая доска — набор колонок
- Колонки с настраиваемыми названиями (To Do / In Progress / Done и пользовательские)
- Карточки: заголовок, описание (Markdown), приоритет (low/medium/high/urgent), дедлайн, метки
- Drag‑and‑drop карточек между колонками и внутри колонки (сортировка)
- Комментарии к карточкам с отметкой времени и автора
- Фильтры: по приоритету, меткам, исполнителю, наличию дедлайна
- Лог активности доски (кто, когда, какое действие)
- Назначение карточки на пользователя (assignee)
- live‑обновления доски при изменениях

**Seed‑данные:** 2 доски, 4 колонки, 20+ карточек, 10+ комментариев

### Вариант 3: Книга рецептов

Общие требования плюс:

**Функциональные:**
- Рецепты: название, описание, время приготовления, сложность, фото (upload), пошаговые инструкции
- Ингредиенты с количеством и единицами измерения (граммы, штуки, мл)
- Категории и теги (завтрак, десерт, веган, быстрое и т.д.)
- Поиск рецептов по названию, ингредиентам («что приготовить из курицы и риса»), тегам
- Планировщик меню на неделю: drag‑and‑drop рецептов в слоты (пн‑вс × завтрак/обед/ужин)
- Автогенерация списка покупок из плана меню (агрегация ингредиентов с суммированием)
- Масштабирование порций: пересчёт ингредиентов на N порций
- Избранное: добавление рецептов в закладки
- Рейтинг рецептов (1–5 звёзд) с сортировкой по среднему рейтингу
- Регистрация / авторизация (JWT), два предзаполненных пользователя; рецепт может быть публичным (виден всем) или приватным (только автор); имя автора отображается на карточке рецепта
- Комментарии к рецептам: авторизованный пользователь оставляет комментарии с отметкой времени и автора; владелец рецепта может удалить любой комментарий

**Seed‑данные:** 25+ рецептов с фото‑заглушками, 50+ ингредиентов, готовый план меню на неделю, 2 пользователя, 20+ комментариев

### Вариант 4: Платформа квизов / опросов

Общие требования плюс:

**Функциональные:**
- Регистрация / авторизация (JWT), роли: автор квиза и участник
- Конструктор квизов: вопросы разных типов (одиночный выбор, множественный выбор, ввод текста, true/false)
- Настройки квиза: лимит времени на вопрос, случайный порядок вопросов, показ правильных ответов после завершения
- Прохождение квиза: таймер, прогресс‑бар, навигация между вопросами
- Автоподсчёт баллов, мгновенный результат с разбором ошибок
- Дашборд автора: список квизов, количество прохождений, средний балл, распределение ответов по каждому вопросу (bar chart)
- Экспорт результатов в CSV (все прохождения конкретного квиза)
- Публичная ссылка на квиз (share link без авторизации для участника)
- Дублирование квиза (clone) для создания вариаций
- Live‑прохождение: пока участник проходит квиз, автор видит в реальном времени (WebSocket) текущее количество активных сессий и поступающие ответы без перезагрузки страницы
- Лог активности квиза: фиксируются события создания/изменения квиза и каждого прохождения (кто, когда, сколько баллов); лог отображается на странице квиза для автора

**Seed‑данные:** 3 квиза (5–10 вопросов каждый), 20+ записей прохождений, 2 пользователя

### Вариант 5: Персональная база знаний / заметки

Общие требования плюс:

**Функциональные:**
- Markdown‑редактор с live preview
- Иерархия: папки / блокноты для группировки заметок
- Теги: присвоение нескольких тегов заметке, облако тегов, фильтрация по тегам
- Полнотекстовый поиск по содержимому заметок (SQLite FTS5 или аналог)
- Избранное: закрепление важных заметок, отдельная вкладка
- История версий: просмотр предыдущих редакций заметки, откат к любой версии
- Связи между заметками: wiki‑ссылки `[[Название заметки]]`, граф связей (визуализация)
- Экспорт заметки в Markdown‑файл и PDF
- Корзина: мягкое удаление с возможностью восстановления в течение 30 дней
- Drag‑and‑drop заметок: перетаскивание заметок между папками и изменение порядка заметок внутри папки
- Автосохранение в реальном времени: изменения сохраняются автоматически по мере набора (без кнопки Save); индикатор состояния «сохраняется… / сохранено N секунд назад» обновляется live

**Нефункциональные (дополнительно):**
- Однопользовательское приложение (без авторизации, zero config)

**Seed‑данные:** 30+ заметок в 5 папках, 15 тегов, 10+ связей между заметками, история версий для 5 заметок

### Вариант 6: Каталог инвентаря / библиотека

Общие требования плюс:

**Функциональные:**
- Элементы: название, описание, категория, количество, фото, штрихкод/артикул
- Иерархические категории (например: Электроника → Ноутбуки → Dell)
- Выдача / возврат элементов: кому выдано, дата выдачи, ожидаемая дата возврата
- История операций по каждому элементу (журнал выдач/возвратов)
- Уведомления о малом остатке: настраиваемый порог для каждого элемента, дашборд «требует пополнения»
- Поиск и фильтрация: по названию, категории, статусу (в наличии / выдано / мало), артикулу
- Дашборд: общая статистика (всего элементов, выдано, на складе), топ выдаваемых, просроченные возвраты
- Импорт элементов из CSV
- Экспорт каталога / отчёта по выдачам в CSV
- Регистрация / авторизация (JWT), два предзаполненных аккаунта с разными ролями: администратор (полный CRUD) и сотрудник (просмотр + оформление выдачи/возврата)
- Уведомления в реальном времени (WebSocket или SSE): при изменении статуса элемента (выдан, возвращён, достигнут порог остатка) все активные пользователи получают уведомление без перезагрузки страницы

**Seed‑данные:** 50+ элементов в 10 категориях, 20+ записей выдач/возвратов, 5 просроченных, 2 пользователя (admin + сотрудник)

## Критерии оценки

- Выполнены все **общие требования** (CRUD, поиск, дашборд, пагинация, адаптивная вёрстка, тесты, CI, Docker Compose, OpenAPI, README)
- Выполнены все **функциональные требования выбранного варианта**
- Приложение поставляется с **seed‑данными** указанного объёма
- **Docker Compose** — приложение запускается в чистом окружении одной командой `docker compose up` без дополнительной настройки (блокирующий критерий: не выполнено — отправка на доработку)
- **AI‑процесс разработки** — ARCHITECTURE.md создан до начала кодирования (проверяется по git‑истории); REPORT.md содержит описание использованных AI‑инструментов и минимум один показательный пример промпта с кратким разбором

## Процесс сдачи

1. **Репозиторий** — студент предоставляет ссылку на GitHub‑репозиторий
2. **Запуск** — преподаватель выполняет:
   ```bash
   git clone <repo> && cd <repo>
   docker compose up
   ```
3. **Проверка функционала** — преподаватель открывает приложение в браузере и проходит по основным сценариям варианта (seed‑данные уже загружены)
4. **API** — преподаватель открывает Swagger UI по адресу `http://localhost:<port>/docs` (или `/redoc`, `/api-docs`) и проверяет эндпоинты
5. **CI** — преподаватель проверяет, что pipeline в GitHub Actions проходит (lint + тесты + сборка)
6. **Демо (5 мин)** — студент показывает приложение, объясняет архитектуру и ключевые решения
